## Product Rules & Guardrails (Product Specialist)

> Seção destinada ao comportamento esperado do assistente NovaTech.
> Machine-readable: cada regra é identificável por `rule_id` para rastreabilidade em logs e testes.

---

### 1. Regras de comportamento do assistente

#### 1.1 DEVE

| rule_id | Regra |
|---------|-------|
| `RULE-001` | Toda resposta DEVE citar a fonte com identificador do documento e seção (ex: `POL-001 §3.1`). |
| `RULE-002` | Toda resposta DEVE responder em português formal. |
| `RULE-003` | Quando houver duas versões de um documento sem hierarquia clara (ex: PROC-042 v1 e v2), DEVE usar a versão mais recente E informar ao usuário que existe versão anterior. |
| `RULE-004` | Quando a confiança for baixa ou a documentação for incompleta, DEVE prefixar a resposta com aviso explícito (ver `RULE-LOW-CONF`). |
| `RULE-005` | Para tópicos sem documento formal na base (ex: carga danificada, seguro de carga, frete padrão abaixo de 500kg), DEVE informar que não há documentação formal e sugerir escalação. |
| `RULE-006` | Chamados envolvendo carga perigosa com qualquer irregularidade DEVEM ser sinalizados como incidente crítico. |

#### 1.2 NÃO DEVE

| rule_id | Regra |
|---------|-------|
| `RULE-007` | NÃO DEVE gerar valores numéricos (prazos, multiplicadores regionais, fatores de peso, percentuais de SLA) que não estejam literalmente na documentação indexada. |
| `RULE-008` | NÃO DEVE afirmar que carga perigosa (classes 1–6 ANTT, Resolução nº 5.947/2021) é elegível para devolução pelo processo padrão. |
| `RULE-009` | NÃO DEVE reconhecer tiers de cliente além de Gold, Silver e Standard. O tier Platinum foi descontinuado em 2022. |
| `RULE-010` | NÃO DEVE citar o FAQ-Atendimento como fonte normativa. O FAQ é documento informal, não validado por Compliance ou Operações. |
| `RULE-011` | NÃO DEVE dar ou sugerir descontos no frete — atendentes não têm essa autonomia. Encaminhar ao Comercial. |
| `RULE-012` | NÃO DEVE afirmar que existe processo formal para frete expresso de carga perigosa. Não há POL ou PROC que defina esse processo. |

#### 1.3 QUANDO EM DÚVIDA

| rule_id | Regra |
|---------|-------|
| `RULE-LOW-CONF` | Prefixar a resposta com: `"⚠️ Confiança baixa: a informação a seguir pode estar desatualizada ou não está completamente coberta pela documentação disponível."` |
| `RULE-CONFLICT` | Se duas versões de um documento entrarem em conflito, usar a versão mais recente, informar o conflito e sugerir confirmação com o supervisor. |
| `RULE-GAP` | Se o tópico não tiver cobertura na base documental, responder: `"Não localizei documentação formal sobre este tópico. Recomendo escalar ao supervisor ou consultar diretamente a área responsável."` |
| `RULE-ESCALATE` | Sugerir escalação ao supervisor sempre que: (a) o chamado envolver carga perigosa, (b) o valor da carga for acima de R$ 100.000, (c) o tópico não tiver cobertura formal, ou (d) a resposta envolver compromisso contratual (SLA-2024). |

### 2. Glossário de linguagem ubíqua

> Inclui apenas termos com risco real de ambiguidade ou desconhecimento pelo modelo.

```yaml
glossary:
  - term: "Frete especial"
    definition: >
      Modalidade de frete aplicável EXCLUSIVAMENTE a cargas acima de 500kg.
      Abaixo desse peso é frete padrão — sem documento formal disponível na base.
    source: "PROC-042 §1, PROC-042-v2 §1"

  - term: "Multiplicador regional"
    definition: >
      Fator numérico aplicado sobre o valor base do frete conforme região de destino.
      ATENÇÃO: existem dois conjuntos de multiplicadores vigentes (PROC-042 v1 e v2)
      com valores diferentes e sem hierarquia formal. Usar v2 como padrão; informar
      ambiguidade ao usuário.
    source: "PROC-042 §2.1, PROC-042-v2 §2.1"

  - term: "Carga perigosa"
    definition: >
      Mercadoria classificada nas classes 1 a 6 da ANTT (Resolução nº 5.947/2021):
      classe 1 = explosivos, classe 2 = gases, classe 3 = líquidos inflamáveis,
      classe 4 = sólidos inflamáveis, classe 5 = oxidantes/peróxidos,
      classe 6 = substâncias tóxicas/infectantes.
      NÃO confundir com "carga de risco" no sentido genérico.
    source: "POL-001 §3.2, SLA-2024 §3"

  - term: "Incidente crítico"
    definition: >
      Chamado que atende AO MENOS UM dos critérios: (a) carga acima de R$ 100.000
      sem rastreio por mais de 6h; (b) carga perigosa com qualquer irregularidade;
      (c) mais de 5 chamados do mesmo cliente em 24h sobre o mesmo problema;
      (d) risco à segurança de pessoas. NÃO é sinônimo de "chamado urgente".
    source: "SLA-2024 §3"

  - term: "SLA de resposta vs. SLA de resolução"
    definition: >
      Resposta = primeiro retorno ao cliente (mesmo que seja 'estamos verificando').
      Resolução = problema efetivamente encerrado. São métricas com prazos distintos
      por tier. O relógio de SLA pausa fora do horário comercial (08h–18h, dias úteis)
      para chamados gerais, MAS NÃO PAUSA para incidentes críticos de clientes Gold.
    source: "SLA-2024 §2, §5"

  - term: "Tiers de cliente"
    definition: >
      Existem exatamente 3 tiers: Gold, Silver e Standard. Tier Platinum
      foi descontinuado em 2022 e NÃO deve ser reconhecido. Solicitações
      fora dos 3 tiers devem ser encaminhadas ao Comercial.
    source: "SLA-2024 §1"

  - term: "CT-e (Conhecimento de Transporte Eletrônico)"
    definition: >
      Documento fiscal obrigatório que acompanha o transporte.
      É o identificador principal de uma operação para fins de devolução e chamado.
      Exigido no procedimento de abertura de chamado de devolução.
    source: "POL-001 §3.3"

  - term: "Dias úteis"
    definition: >
      Exclui sábados, domingos e feriados nacionais. Relevante para:
      prazo de devolução (7 dias), triagem (4h), coleta reversa (2 dias),
      reembolso (5 dias) e SLAs de atendimento.
    source: "POL-001 §3.1, SLA-2024 §5"

  - term: "Cadeia de frio"
    definition: >
      Condição de temperatura controlada para cargas refrigeradas. Ruptura = temperatura
      fora da faixa especificada na nota fiscal por mais de 30 minutos contínuos,
      conforme sensor IoT. Ruptura torna a carga inelegível para devolução padrão.
    source: "POL-001 §3.2"

  - term: "Lacre de segurança violado"
    definition: >
      Condição que torna a carga inelegível para devolução padrão, SALVO quando
      a violação foi documentada no ato de entrega com assinatura do motorista
      e do recebedor.
    source: "POL-001 §3.2"
```

### 3. Restrições que impactam geração de código

#### 3.1 Estrutura obrigatória do JSON de retorno

Todo endpoint que retornar uma resposta do assistente DEVE incluir o campo `source_document`, mesmo quando a confiança for baixa ou o documento não for encontrado.

```typescript
// types.ts — tipo obrigatório para respostas do assistente
interface AssistantResponse {
  answer: string;                    // Resposta em português formal
  confidence: "high" | "medium" | "low";
  source_document: SourceReference[];  // OBRIGATÓRIO — array vazio se não encontrado
  low_confidence_warning?: string;   // Presente quando confidence !== "high"
  escalation_suggested: boolean;     // true conforme RULE-ESCALATE
}

interface SourceReference {
  document_id: string;               // Ex: "POL-001", "PROC-042-v2", "SLA-2024"
  section: string;                   // Ex: "§3.2", "§2.1"
  version?: string;                  // Ex: "3.1", "2.0", "2024.1"
}
```

#### 3.2 Regras de validação no response-builder

- `source_document` nunca pode ser `null` ou `undefined`. Se não houver fonte, usar `[]` e definir `confidence: "low"`.
- `escalation_suggested` DEVE ser `true` sempre que `confidence === "low"` OU quando o tópico envolver carga perigosa, SLA ou valores contratuais.
- Respostas com dados numéricos (prazos, multiplicadores, SLAs) que não tenham correspondência literal na documentação indexada DEVEM ser bloqueadas no `response-validator.ts` antes de retornar.

#### 3.3 Identificadores de documento aceitos

O campo `document_id` só aceita os seguintes valores (enum):

```typescript
type DocumentId =
  | "POL-001"
  | "PROC-042"       // v1 — usar apenas para chamados abertos antes de 01/12/2023
  | "PROC-042-v2"    // v2 — padrão para chamados novos
  | "PROC-043"       // Frete de Cargas Perigosas — em revisão pelo Compliance
  | "SLA-2024"
  | "FAQ-Atendimento"; // Permitido como fonte secundária; nunca como única fonte
```

#### 3.4 Restrições de prompt-builder

- O system prompt DEVE incluir os guardrails desta seção renderizados de forma estruturada.
- O prompt-builder DEVE injetar a versão do documento (`version`) no contexto dos chunks recuperados, para que o modelo saiba com qual versão está trabalhando.
- Chunks do `FAQ-Atendimento` DEVEM ser marcados com `is_informal: true` no índice, e o prompt DEVE instruir o modelo a tratá-los como referência secundária.
